# Audience

The **Audience** tab of a form holds the people the form is for and the facts you keep about each of them. Each person's values fill the form when they open it, so a form can greet someone by name or ask about their own company. Test people let you try that personalized form as someone, without sending a link or counting the result as a real response.

To use the properties in the form and check it in the designer, see [Personalized Forms](/docs/end-users/forms/personalized-forms). To run a whole personalized survey, from import to export, follow [Run a personalized survey](/docs/end-users/guides/run-a-personalized-survey).

To open it, open the form from the **Forms** list, click the section menu next to the form name (it shows **Overview**), and choose **Audience**. The tab appears when your Endatix deployment has personalization turned on.

## People and properties

The tab has two views, **People** and **Properties**. Each shows its count in the view switch. A form with properties also has a third view, [**Preview as**](#preview-as), for people who can edit the form.

- A **property** is one fact kept for each person on this form, such as a first name, a company, or a plan. Each property is a column in the people table.
- A **person** is someone in the form's audience. Endatix recognizes the same person on every form in your organization by the **match key**, for example their email. Removing someone takes them off this form only.

### Add a property

1. On the **Properties** view, click **Add property**.
2. Enter a **Name**, such as `First name`. Endatix builds the **variable name** from it (`first_name`). The variable name never changes, even if you rename the property later.
3. Choose a **Type**. Values are checked against the type when people are added or edited.
4. Click **Add property**.

Use the variable name in the form the same way as any other variable, in braces: a title of `Welcome, {first_name}` shows each person their own first name. See [Text Piping](/docs/end-users/forms/form-builder/text-piping) for where you can use it.

### Check which values the form uses

If you can edit the form, the **Properties** view also shows how the saved form uses each property:

- **Used in form** is **Used** when the form reads the variable, and **Not used** when nothing in it does.
- **Filled in (real)** counts the real people who have a value for it, for example **2 of 3 filled**. Test people are not counted. With no real people yet, it says **No real participants**.

<Shot

The counts follow the last saved version of the form. Save the form in the designer to update them. The designer's **Diagnostics** tab shows the same gaps as warnings while you edit: see [Fix the Personalization warnings](/docs/end-users/forms/personalized-forms#fix-the-personalization-warnings).

### Add people

The **People** view lists everyone on the form, with one column per property.

<Shot
  alt="People view of the Audience tab: Import CSV, Personalized links and Add person buttons, the All people filter, and a table of four people. jordan.lee@example.com carries a 1 not filled in mark and qa.tester@example.com a Test badge. The Link column shows Opened for alex.kim@example.com and Issued for the other real people, and each row has Test as this participant, Edit and Remove actions"
  sources={{ light: PeopleLight, dark: PeopleDark }}
/>

- **Add person** adds one person: enter their identifier (the match key, for example **Email**) and, optionally, a value for each property.
- **Import CSV** adds many at once from a file with one person per row. Choose the column that identifies people and the property each other column fills, then review and import. Nothing is written until the last step.
- **Personalized links** creates one link per real person who has none yet and downloads them as a file to send from your own email or panel tool. Each link opens that person's own response, and resumes it on later opens.

Two marks help you check the list before you send links:

- **Link** shows each real person's link: **Not issued**, **Issued**, or **Opened**. Click **Opened** to see the response the link started. A test person never gets a link. The column appears once anyone on the form has a link.
- **N not filled in** next to a person means the saved form reads values they don't have. Hover over it to see which ones. Fill them in with **Edit**, or the form shows those places empty for that person. Only people who can edit the form see this mark.

## Preview as

**Preview as** shows the saved form the way one participant gets it, with their values filled in. Use it to check a real participant's form before you send links, without opening their link or creating a submission. It needs permission to edit the form.

1. On the **Audience** tab, click **Preview as** in the view switch.
2. Pick a participant on the left. **Test participants** are listed first. To find anyone else, real participants included, type part of their identifier in **Find any participant**.
3. Read the form on the right. Use the arrow keys to move to the next or previous participant.

<Shot
  alt="Preview as view: Find any participant above a Test participants list with qa.tester@example.com selected; on the right, qa.tester@example.com with a Test badge, Test as this participant and Edit values buttons, the values First name Sam, Company Contoso, Tier Gold and Region empty, the note Every value is filled in, Saved form, last saved 17 seconds ago, and the form starting Welcome, Sam"
  sources={{ light: PreviewAsLight, dark: PreviewAsDark }}
/>

Above the form, the participant's values are listed, with a dash for an empty one, and a note names the values the form reads that they don't have (**Not filled in: …**), or says **Every value is filled in**. Below that is when the form was last saved: the preview always shows the saved version, so save in the designer first. Answers you type in the preview are not saved.

- **Edit values** changes the participant's values; the preview updates with them.
- **Test as this participant** opens a test submission with the same values, as from the **People** view. It needs permission to test forms.

The choice is kept in the page address, so you can share a link to one participant's preview with someone who can edit the form. To preview a draft before you save it, use [Preview as in the designer](/docs/end-users/forms/personalized-forms#preview-the-form-as-a-participant).

## Open a participant's page

Click a person's identifier to open their page on this form. It needs permission to edit the form.

<Shot
  alt="Participant page for alex.kim@example.com: Test as this participant, Edit values and Remove buttons, a Values card with First name Alex and Company Fabrikam, a Link card with status Opened, when it was opened and a View response link, and a Submissions table with one In progress submission from a Personalized link"
  sources={{ light: ParticipantLight, dark: ParticipantDark }}
/>

- **Values** lists the person's value for each property.
- **Link** shows their personalized link's status, when it was opened, and the response it started. It appears only once a link was issued, so a test person never has it.
- **Submissions** lists their newest submissions on this form, up to 50, with the status and where each came from: **Personalized link**, **On behalf**, or **Test as this participant**. Click **View** to open one.

The page has the same actions as the row: **Copy test link** for a test person, **Test as this participant**, **Edit values**, and **Remove**. Click **Audience** at the top to go back to the list.

## Test people

A **test person** exists only for testing on this form. They are never sent a personalized link and do not count as part of the audience. Use test people to see the form the way a respondent with those values sees it.

You choose whether someone is a test person when you add them. It cannot be changed later: to turn a test person into a real one, remove them and add them again.

### Add a test person

1. On the **People** view, click **Add person**.
2. Enter the identifier and the property values you want to test with.
3. Select **Add as test person**.
4. Click **Add person**.

<Shot
  alt="Add person panel with Email qa.reviewer@example.com, First name Robin, Company Contoso, and the Add as test person checkbox selected"
  sources={{ light: AddTestPersonLight, dark: AddTestPersonDark }}
/>

The person appears in the table with a **Test** badge next to their identifier.

### Import test people

1. On the **People** view, click **Import CSV** and choose the file.
2. Map the columns, then click **Continue** to reach **Review**.
3. Select **Import as test people**.
4. Click **Import**. The button names the row count, for example **Import 2 rows**.

<Shot
  alt="Import people panel on the Review step with Import as test people selected and the note Existing people are skipped"
  sources={{ light: ImportAsTestLight, dark: ImportAsTestDark }}
/>

With **Import as test people** on, only people new to this form are added, as test people. A person already on the form is skipped and keeps their values, so a test import never changes a real person. The outcome counts both, for example *1 added as test people, 1 skipped because they are already on this form*.

### Filter real and test people

Once the form has people, a filter above the table shows **All people**, **Real people**, or **Test people**. The choice is kept in the page address, so you can bookmark or share a filtered view.

<Shot
  alt="People filter open, with All people selected and Real people and Test people as the other options"
  sources={{ light: TestFilterLight, dark: TestFilterDark }}

## Test as this participant

**Test as this participant** opens the form as that person, with their current values, in a new browser tab. It is the flask icon in the row's actions and a button on the participant's page, and it needs permission to test forms.

1. On the **People** view, find the person. A test person is the usual choice, but any person works.
2. Click **Test as this participant** in their row, or on their page.

Each click creates a new test submission for that person, on the latest saved version of the form.

<Shot
  src={require("./audience-test-as-this-participant.webp").default}
  alt="The form opened as the test person Sam from Contoso: the heading reads Welcome, Sam, the first question asks how easy it was to set up Endatix at Contoso, and the round Test inspector button with its TEST tag sits at the bottom right"
/>

Testing as a real person does not use up their personalized link. When they open it, they still get a new real response of their own.

A test submission does not count toward [**Limit one per user**](/docs/end-users/sharing/single-submission). On the Submissions page, the **Submission Type** filter shows or hides test submissions, and an export includes them only when **Include test submissions** is on.

## Test inspector

The round button with a **TEST** tag at the bottom right of a test submission is the **Test inspector**. Click it to see who you are submitting as and the values the form was opened with, to open the submission or the participant in Hub, and to **Start over**.

You see it when you can test forms. Anyone else who opens the same test submission sees only *You are submitting a test submission*, and real respondents see neither. See [Testing Submissions](/docs/end-users/submissions/testing-submissions#read-the-test-inspector) for each row and panel.

## Start over

**Start over** is in the Test inspector of a test submission opened with **Test as this participant**. It discards the current test submission and opens a new one for the same person.

Use it after you change the person's values or edit the form: the new test submission picks up the person's current values and the latest saved form. To try different values, edit the person on the **People** view, then click **Start over** in the form's tab.

If the person was removed from the form in the meantime, **Start over** goes away and the Test inspector says *This person is no longer on this form, so this test submission cannot start over.* Add a test person again and use **Test as this participant**.

## Copy test link

**Copy test link** gives you a link to a new test submission as a test person, to send to a colleague who has no Endatix login. They open it in any browser and fill in the form with that person's values, also on a private form.

It is the link icon, first in a test person's row actions, and the first button on a test person's page. Real people do not have it. You see it when you can test forms, edit the form, and view, edit, or export submissions.

<Shot
  alt="People table with qa.tester@example.com, marked Test, and alex.kim@example.com. The test person's row actions start with the link icon, Copy test link, before Test as this participant, Edit and Remove; the real person's row has no link icon, so the other three line up"
  sources={{ light: CopyTestLinkRowLight, dark: CopyTestLinkRowDark }}
/>

1. On the **People** view, click **Copy test link** in a test person's row, or on their page.
2. Choose the **Link lifetime**, from **1 hour** to **60 days**. It starts at **7 days**.
3. Click **Create and copy link**. Hub creates the test submission and copies its link.

<Shot
  alt="Copy test link panel for qa.tester@example.com after a copy: Link lifetime 7 days, the Test link with its share address and a copy button, Expires in 7 days, and the Create and copy another button"
  sources={{ light: CopyTestLinkLight, dark: CopyTestLinkDark }}
/>

The panel also shows the link with **Copy this link**, in case your browser did not allow the copy. Click **Create and copy another** for a second link: each copy opens its own new test submission, with the person's current values and the latest saved form.

Anyone with the link can fill in that one test submission until it is completed or the link expires, with no sign-in. It opens nothing else. The submission is a test submission like any other: it shows under **Submission Type: Test** on the Submissions page, stays out of exports unless you include test submissions, and can be deleted there.

## Limitations

- **Test status is set once.** You cannot switch a person between test and real. Remove them and add them again.
- **Test people get no personalized links.** **Personalized links** skips them; use **Copy test link** to share a test, and a test import never touches people already on the form.
- **Start over needs the person.** It works only while the person is still on the form.
- **No Test inspector in embeds.** An embedded form shows the plain test notice with **Start over**.
