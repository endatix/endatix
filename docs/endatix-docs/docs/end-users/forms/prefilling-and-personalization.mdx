# Prefilling and Personalization

## What Is Prefilling?

Prefilling means a form arrives with some of its values already supplied, based on information you already have about the respondent — a name, an account ID, a plan tier — so they see fewer blank fields and the form feels tailored to them rather than generic.

Endatix supports three ways to pre-fill a form:

* **Prefill from a Property** — when the form has [Participants](/docs/end-users/forms/audience), pick a Property on a question's **Personalization** tab, and each participant's form starts with their own value. See [Prefill from a Property](#prefill-from-a-property).
* **Query string variables** (most of this guide) — values are read directly in the respondent's browser from the link they open, with no backend involved. It's the simplest option and well suited to personalized links in an email campaign or CRM outreach — append the data to the URL, and the form does the rest.
* **Access-token prefilling** — your backend creates a submission with data it already holds and issues a scoped, expiring access token for it. This relies on the Endatix API and is aimed at developers integrating Endatix server-side; see [Form Prefilling and Sharing](/docs/guides/form-prefilling) for details.

The next sections cover query string variables. Beyond prefilling a question, the same variables can:

* **Drive logic** — show, hide, or branch based on where the respondent came from.
* **Personalize text** — pipe the value into a question's title or description.

## Creating a Variable

Variables are declared in the Form Builder, not on any single question — they belong to the survey as a whole.

:::tip[Values from the Audience tab need no variable]
If the values come from the form's [Audience](/docs/end-users/forms/audience), each property is already a variable: use `{first_name}` in the form without adding it here. A custom variable is only for a value passed in the link, as on this page, or calculated in the form. See [Personalized Forms](/docs/end-users/forms/personalized-forms).
:::

1. Open your form in the Form Builder and click the **Survey settings** icon (the sliders icon above the Property Grid) to open **Survey Settings**.
2. Select the **Conditions** category.
3. Under **Custom variables**, click **+ Add new variable**.
4. Give it a short, descriptive **Name** — letters, numbers, and underscores, unique across the survey. This is the name you'll use in expressions as `{variableName}` and match against a query string parameter of the same name.
5. Leave **Expression** empty. An empty expression means the variable's value comes entirely from outside the form (the query string) — Endatix Hub never overwrites it with a computed value.

<ThemedImage

  sources={{
    light: useBaseUrl(customVariablesLight),
    dark: useBaseUrl(customVariablesDark),

/>

:::tip[Saving the value with the submission]
The **Add to the survey results** checkbox controls whether the variable's current value is written into the submission data (`survey.data`) alongside the question answers. Enable it if you want to keep a record of, for example, which campaign a respondent arrived from.
:::

## Passing Values Through the URL

Once your form is [public](/docs/end-users/forms/submission-expiration), its fill-out link looks like:

```
https://app.endatix.com/share/{formId}
```

Append query string parameters to that link, and any parameter whose name isn't reserved (see below) becomes a variable in the survey automatically — no code required. Chain multiple values with `&`:

<pre style={{ padding: 'var(--ifm-pre-padding)', borderRadius: 'var(--ifm-code-border-radius)', background: 'var(--ifm-pre-background)', overflowX: 'auto' }}>
<code style={{ fontFamily: 'var(--ifm-font-family-monospace)', fontSize: 'var(--ifm-code-font-size)', background: 'none', color: 'var(--ifm-font-color-base)' }}>
https://app.endatix.com/share/1442869143157080064<mark style={{ color: 'var(--ifm-color-primary)', fontWeight: 'bold', backgroundColor: '#ffe066', padding: '0.05em 0.0em', borderRadius: '0.25em' }}>?first_name=Jordan&campaign=spring_launch</mark>
</code>
</pre>

This link sets two variables: `first_name` to `Jordan` and `campaign` to `spring_launch`.

A few names are reserved for other platform features and are never turned into variables, even if present in the URL: **`token`**, **`theme`**, **`language`**, and **`lang`**. Avoid naming your own variables after these.

:::info[Values are always text]
Query string values arrive as plain strings. SurveyJS automatically converts a numeric- or boolean-looking value before an expression uses it — the same conversion (and the same edge cases with leading zeros or a leading `+`) described in [Type Conversion in Expressions](/docs/end-users/forms/form-builder/logic-expressions#type-conversion-in-expressions-the--prefix). Use the `{#variableName}` form if you need the exact, unconverted text.
:::

The parameters stay in the address bar after the page loads — Endatix Hub doesn't strip them, so the link stays shareable and bookmarkable with the same pre-fill data.

If the form is embedded in your own page rather than opened on its share link, the respondent's URL is yours and Endatix never sees these parameters. Pass the same pairs on the embed snippet's `data-prefill` attribute instead - see [Embedding a Form](/docs/end-users/sharing/embedding#personalize-an-embedded-form).

## Prefilling a Question

With the variable in place, point a question at it using **Default value expression** — a standard SurveyJS property available on every question type.

Using a **Single-Line Input** question as an example:

1. Select the question in the Designer (for example, a "First Name" question).
2. In the Property Grid, search for **default value** to jump straight to the field, or find it under the question's **Conditions** category.
3. Set **Default value expression** to `{first_name}`.

<ThemedImage
  alt="Default value expression field on a Single-Line Input question set to the first_name variable"
  sources={{
    light: useBaseUrl(defaultValueLight),
    dark: useBaseUrl(defaultValueDark),
  }}
/>

:::tip[Default value expression, not Set value expression]
**Default value expression** only seeds the question's *starting* value — the respondent can still review and change it. **Set value expression** keeps recalculating and would silently overwrite anything the respondent types, so avoid it for prefilling. If the query parameter is missing from the URL, the variable is simply empty and the question starts blank — no error.
:::

## Using Variables in Logic

A variable behaves exactly like a question or [calculated value](/docs/end-users/forms/form-builder/logic-expressions#1-calculated-values-background-computations) inside an expression, so it works in any condition Endatix Hub accepts — not just in **Default value expression**.

For example, show a question only for respondents who arrived through a specific campaign link:

```json
{
  "type": "comment",
  "name": "campaign_feedback",
  "title": "What made you click through from our spring email?",
  "visibleIf": "{campaign} = 'spring_launch'"
}
```

See [Logic Expressions](/docs/end-users/forms/form-builder/logic-expressions) for the full set of operators and functions you can combine a variable with.

## Using Variables in Text Piping

A variable can also be piped directly into a question's title or description, personalizing the form's own wording — not just its logic. Reference it the same way, in curly braces. (The same syntax pipes a respondent's earlier *answers* too — see [Text Piping](/docs/end-users/forms/form-builder/text-piping).)

Say a personalized link tells you which brand a respondent is being asked about:

<pre style={{ padding: 'var(--ifm-pre-padding)', borderRadius: 'var(--ifm-code-border-radius)', background: 'var(--ifm-pre-background)', overflowX: 'auto' }}>
<code style={{ fontFamily: 'var(--ifm-font-family-monospace)', fontSize: 'var(--ifm-code-font-size)', background: 'none', color: 'var(--ifm-font-color-base)' }}>
https://app.endatix.com/share/1442869143157080064<mark style={{ color: 'var(--ifm-color-primary)', fontWeight: 'bold', backgroundColor: '#ffe066', padding: '0.05em 0.0em', borderRadius: '0.25em' }}>?brand_name=Spotify</mark>
</code>
</pre>

A Rating question can pipe `{brand_name}` straight into its title:

```json
{
  "type": "rating",
  "name": "brand_rating",
  "title": "How would you rate {brand_name}?"
}
```

When that respondent opens the link, the title renders with the value already filled in:

## Prefill from a Property

When the form has Participants, a question can start with each participant's value of a Property, such as their family size or region. **Prefill from** sets this up in the designer without typing an expression.

It needs personalization turned on for your Endatix deployment, permission to edit the form, and at least one Property on the form's [Participants](/docs/end-users/forms/audience#add-a-property) tab.

1. Open the form in the designer and select the question.
2. In the Property Grid, open the **Personalization** tab (the person icon).
3. In **Prefill from**, pick a Property.

<Shot
  alt="Personalization tab of the household_size question: Prefill from set to Family size, and Allow respondent to edit turned on"
  sources={{ light: PrefillFromLight, dark: PrefillFromDark }}
/>

Pick a Property that fits the question:

| Property type | Question it fits |
| --- | --- |
| Text | Single-Line Input (plain text), Long Text |
| Number | Single-Line Input with **Input type** Number, Rating, Slider |
| Yes/No | Yes/No (Boolean) |
| Date | Single-Line Input with **Input type** Date |
| Date-time | Single-Line Input (plain text, or **Input type** Date and Time) |
| Single choice | Dropdown, Radio Button Group, Button Group |
| Multiple choice | Checkboxes, Multi-Select Dropdown (tag box) |

A Property of another type can leave the question empty or with a value it cannot show.

To check the result, open the **Preview** tab and pick a participant in [**Preview as**](/docs/end-users/forms/personalized-forms#preview-the-form-as-a-participant). The question starts with their value.

<Shot
  alt="Preview tab running the form as qa.tester@example.com: Household size reads 4, Region reads North, Renewal reads 15.03.2027, 09:30, and Age in months reads 408"
  sources={{ light: PrefillPreviewLight, dark: PrefillPreviewDark }}
/>

### Allow respondent to edit

After you pick a Property, **Allow respondent to edit** appears below it, on by default.

- **On**: the participant sees their value and can change it.
- **Off**: the answer is read-only in the form.

**Allow respondent to edit is not a security control.** It only changes the form in the browser: the saved answer can still be changed outside the form, for example through the API. Use it to keep a value the participant should only confirm, not to protect data.

### Custom expression

If the question's **Default value expression** is a calculation, such as `{age} * 12`, **Prefill from** shows **Custom expression** and a link to that expression. The calculation stays as you wrote it. It changes only when you pick a Property, and **Undo** brings it back. Edit the calculation itself in [Default value expression](#prefilling-a-question).

<Shot
  alt="Personalization tab with Prefill from set to Custom expression and the note This question's default is a calculation. It stays as written unless you pick a Property. Edit it in Default value expression."
  sources={{ light: PrefillCustomLight, dark: PrefillCustomDark }}
/>

### Date and time Properties

A date-time Property fits a plain text question and a date-and-time question (**Input type** `datetime-local`). A date-and-time question shows the time as it is stored on the participant, without the time zone: a renewal stored as 09:30 shows 09:30 to every respondent, whatever their own time zone.

### When the tab is missing or disabled

| What you see | Why |
| --- | --- |
| No **Personalization** tab | Personalization is off for the deployment, you cannot edit the form, or no Property can fill this question type (a matrix, a file upload, an HTML block). |
| **Prefill from** disabled, with a link to **Participants** | The form has no Properties yet. Add one on the Participants tab. |

### What is saved

**Prefill from** writes two standard SurveyJS properties and nothing else:

- `defaultValueExpression`: `{family_size}`, or `edxLocalDateTime({renewal_date})` on a date-and-time question.
- `readOnly`: `true` when **Allow respondent to edit** is off.

So you can write the same result by hand in the JSON editor, and a form edited that way shows the Property in **Prefill from**:

```json
{
  "type": "text",
  "name": "household_size",
  "title": "Household size",
  "inputType": "number",
  "defaultValueExpression": "{family_size}",
  "readOnly": true
}
```

## Important Considerations

* Reserved names (`token`, `theme`, `language`, `lang`) are never captured as variables, regardless of what's in the URL.
* A variable with a blank expression stores nothing until a value is set — either by a matching query string parameter or, later, by your own logic (a trigger, another expression). It is not part of the form's respondent-facing UI.
* Query string values are strings first; numeric-looking values are converted the same way question answers are (see [Type Conversion in Expressions](/docs/end-users/forms/form-builder/logic-expressions#type-conversion-in-expressions-the--prefix)).
* Variable names must be unique across variables, calculated values, and questions in the same survey.

## Technical Reference (JSON Schema)

A variable created through **Custom variables** is stored on the survey as a [`calculatedValues`](/docs/end-users/forms/form-builder/logic-expressions#1-calculated-values-background-computations) entry with no `expression` — declaring the name without computing a value. **Default value expression** is a standard SurveyJS question property.

```json
{
  "calculatedValues": [
    { "name": "first_name" },
    { "name": "campaign" }
  ],
  "pages": [
    {
      "name": "page1",
      "elements": [
        {
          "type": "text",
          "name": "attendee_name",
          "title": "First Name",
          "defaultValueExpression": "{first_name}"
        }
      ]
    }
  ]
}
```
