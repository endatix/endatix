# System Requirements

Endatix ships as two deployable parts: the **Endatix API** (.NET) and the **Endatix Hub** (Next.js). Run the API on its own for headless, API-only use — the Hub always needs a reachable API. Both run on **macOS, Windows (including WSL), and Linux**.

## Check what you have

```bash
dotnet --list-sdks   # need 10.0.100 or newer
node --version       # need v20.9.0 or newer
pnpm --version       # need 9.0.0 or newer
docker --version     # optional — for Compose self-hosting
```

## Databases

Pick **one** provider per deployment and set it in [Persistence Settings](/docs/configuration/settings/persistence-settings). Endatix stores form and submission payloads in **native JSON column types**, so the provider *version* matters — not just the vendor.

### SQL Server 2025 or later

Migrations declare payload columns as `json`, a type added in SQL Server 2025. On 2022 and earlier they fail with `Cannot find data type json`. Azure SQL Database supports the type.

### PostgreSQL `pg_trgm` extension

Data-list label search uses trigram indexes, and the migration that creates them fails without `pg_trgm`. Create it before you migrate:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

Managed hosts may need the extension allowlisted first — on Azure Database for PostgreSQL that is the `azure.extensions` server parameter, which [Azure Deployment](/docs/building-your-solution/deployment/azure) covers and the sample Bicep sets for you.

## Browsers

The Hub — including public form-filling pages — targets the Next.js 16 baseline:

- **Chrome** 111+
- **Edge** 111+
- **Firefox** 111+
- **Safari** 16.4+

Older browsers load the page but may fail on modern JavaScript syntax — see [Next.js supported browsers](https://nextjs.org/docs/architecture/supported-browsers).

## Optional tooling

Needed only for the path you take:

- **Docker Desktop** (Compose v2) — [self-hosting with Compose](/docs/building-your-solution/deployment/self-hosting)
- **Kubernetes + Helm 3** — cluster self-hosting, same images and database rules; Hub is configured with [request-time `ENDATIX_*` env](/docs/developers/hub/environment)
- **Azure CLI / SWA CLI** — [Azure Deployment](/docs/building-your-solution/deployment/azure)
- **`dotnet-ef`** — running migrations by hand instead of at startup ([Persistence Settings](/docs/configuration/settings/persistence-settings))
- **Git** — [installing from the repository](/docs/getting-started/setup-repository)
