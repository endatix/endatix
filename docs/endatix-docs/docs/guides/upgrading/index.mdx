# Upgrading Endatix

Upgrade the Endatix API and Endatix Hub together, to the same version. When you skip versions, read the guide for every version in between, oldest first. Each guide links to its API and Hub release notes.

- [v0.9.3](/docs/guides/upgrading/v0-9-3): migrate a custom MailKit transport to MailKit 5, and on the Reporting preview, merge then force a backfill for forms whose checkbox, copied-choice or matrix exports changed.
- [v0.9.2](/docs/guides/upgrading/v0-9-2): give the Hub a strong `AUTH_SECRET` and drop `SESSION_SECRET`, set `DefaultTenantId` when Keycloak is enabled, expect 403 for signed-in requests without a tenant, move legacy tenant-0 Keycloak users once, and assign roles from system code with `ISystemRoleAssignment`.
- [v0.9.1](/docs/guides/upgrading/v0-9-1): stop every 0.9.0 API instance first, move screen-out handlers to `submission.closed`, and rebuild participant columns.

## When your release includes `NumberFormDefinitions`

Before upgrading production, rehearse the migration on a representative database copy. Record how many forms and definitions are queued in `LegacyDraftUpgrades` and time the whole queue. Compare the finish time with your request and database command timeouts. Choose a maintenance window that allows for a full retry.

If you apply generated SQL with auto-migrations off, run `dotnet ef database update` for `AppDbContext` against **the same database**, using the deployed release's provider project. The EF seeder holds locks for every processed form until the whole queue commits. Legacy definitions remain addressable by ID, but a write to an early form can wait for later forms to finish or time out. An interruption before commit rolls back the whole queue transaction; rerun the finisher.

Check both conditions before declaring the data upgrade complete: `__EFMigrationsHistory` contains `20261128073201_NumberFormDefinitions` (PostgreSQL) or `20261128073154_NumberFormDefinitions` (SQL Server), **and** `LegacyDraftUpgrades` has zero rows.

For the later publishing cutover, follow the release notes' **Compatibility** table. Upgrade through the required intermediate stable release, deploy the compatible Hub, and drain incompatible writers. Reconcile late edits and verify the second numbering pass and unique index before enabling production publishing.
