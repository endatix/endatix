# Upgrade to Endatix 0.9.3

This page covers an upgrade from 0.9.2. It applies to hosts that export submissions with Reporting (the preview) and read the indicator columns of checkboxes or tag boxes.

## Before you start

- **Read the release notes of every version you skip.** An upgrade that skips 0.9.2 also needs the [0.9.2 guide](/docs/guides/upgrading/v0-9-2).

## Unanswered checkboxes export empty cells {/* #unanswered-checkboxes-export-empty-cells */}

**What changed (breaking for the Reporting preview):** the indicator columns of an unanswered checkbox or tag box with its own choices no longer write `0` where the respondent may not have seen it. Its columns, Other and None included, are empty:

- in an incomplete submission, which may have ended before the question;
- in a completed submission, when a visibility condition (`visibleIf`) or `visible: false` on the question, or on a panel, dynamic panel or page that holds it, could hide it, or when the form uses its name for two questions.

A question nothing could hide, skipped in a completed submission, still writes `0`. An answered question writes `1` and `0` as before. Copied choices, loops and rankings follow the same rule since 0.9.2. The Crunch codebook is unchanged; Crunch imports an empty cell as No Data. See [Empty Cells](/docs/end-users/submissions/exporting-submissions#empty-cells).

**Who is affected:** forms with checkboxes or tag boxes that can be hidden, or that incomplete submissions leave unanswered, and any analysis that counts those `0`s.

**What to do:**

- Exports read the rows stored when each submission was saved, so existing rows keep their `0`s until they are rewritten. A backfill with `force=true` (`POST forms/{formId}/submissions/backfill`) rewrites them. Without a compile first, an unanswered question in an incomplete submission turns empty, and a completed submission keeps its `0`s.
- To also empty the completed submissions whose question could be hidden, compile the form's schema first (`POST forms/{formId}/reporting/compile-schema`; merge mode is enough, and it records which questions can be hidden), then backfill with `force=true`. In the Hub, only **Rebuild reporting data…** with **Full recompile** does both: a rebuild without it skips rows that have not changed.

## Other text with a choice comment box {/* #other-text-with-choice-comment-box */}

**What changed:** a checkbox with Other whose regular choice shows a comment box (**Add a comment box** in the Creator) now exports its Other column as `1` and the typed text in its Other text column. SurveyJS stores the typed text of such a checkbox in its value, and 0.9.2 read it from the question's comment, so it exported `0` and an empty text. Radio button groups and dropdowns with a choice comment box still keep the typed text in the comment, and export as before. A tag box's choices show no comment box, so a tag box follows `storeOthersAsComment`: with it `false`, its typed text is now exported too.

**What to do:**

- Compile the form's schema (`POST forms/{formId}/reporting/compile-schema`, with `replace=true` or in merge mode: both record that the text is in the value), then backfill with `force=true` (`POST forms/{formId}/submissions/backfill`). Without the compile, new submissions keep exporting `0`.
- In the Hub, **Rebuild reporting data…** with **Full recompile** does both.
