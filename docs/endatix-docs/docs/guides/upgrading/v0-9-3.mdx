# Upgrade to Endatix 0.9.3

This page covers an upgrade from 0.9.2. It applies to hosts that export submissions with Reporting (the preview) and read the indicator columns of checkboxes or tag boxes.

## Before you start

- **Read the release notes of every version you skip.** An upgrade that skips 0.9.2 also needs the [0.9.2 guide](/docs/guides/upgrading/v0-9-2).

## Unanswered checkboxes export empty cells {/* #unanswered-checkboxes-export-empty-cells */}

**What changed (breaking for the Reporting preview):** the indicator columns of an unanswered checkbox or tag box with its own choices no longer write `0` where the respondent may not have seen it. Its columns, Other and None included, are empty:

- in an incomplete submission, which may have ended before the question;
- in a completed submission, when a visibility condition (`visibleIf`) or `visible: false` on the question, or on a panel, dynamic panel or page that holds it, could hide it, or when the form uses its name for two questions.

A question nothing could hide, skipped in a completed submission, still writes `0`. An answered question writes `1` and `0` as before. Copied choices, loops and rankings follow the same rule since 0.9.2. The Crunch codebook is unchanged; Crunch imports an empty cell as No Data. See [Empty Cells](/docs/end-users/submissions/exporting-submissions#empty-cells).

**Who is affected:** forms with checkboxes or tag boxes that can be hidden, or that incomplete submissions leave unanswered, and any analysis that counts those `0`s.

**What to do:**

- Exports read the rows stored when each submission was saved, so existing rows keep their `0`s until they are rewritten. A backfill with `force=true` (`POST forms/{formId}/submissions/backfill`) rewrites them. Without a compile first, an unanswered question in an incomplete submission turns empty, and a completed submission keeps its `0`s.
- To also empty the completed submissions whose question could be hidden, compile the form's schema first (`POST forms/{formId}/reporting/compile-schema`; merge mode is enough, and it records which questions can be hidden), then backfill with `force=true`. In the Hub, only **Rebuild reporting data…** with **Full recompile** does both: a rebuild without it skips rows that have not changed.

## Copies of copied choices export 0 for shown choices {/* #copies-of-copied-choices */}

**What changed:** a checkbox or tag box that copies its choices from a question that copies its own (for example `pick` copies the selected choices of `aware`, which copies `brands`) now writes `0` for a choice the respondent was shown and did not pick. In 0.9.2 every unpicked choice of such a copy was empty. With the selected mode the copy shows what the source question picked; with all or unselected it shows what the source question was shown, when that can be worked out. See [Empty Cells](/docs/end-users/submissions/exporting-submissions#empty-cells).

**What to do:** compile with `replace=true`, then backfill; see [Refresh stored rows](#refresh-stored-rows).

## Other text with a choice comment box {/* #other-text-with-choice-comment-box */}

**What changed:** a checkbox with Other whose regular choice shows a comment box (**Add a comment box** in the Creator) now exports its Other column as `1` and the typed text in its Other text column. SurveyJS stores the typed text of such a checkbox in its value, and 0.9.2 read it from the question's comment, so it exported `0` and an empty text. Radio button groups and dropdowns with a choice comment box still keep the typed text in the comment, and export as before. A tag box whose choice still has the comment box setting in its JSON (written by hand, or kept from a question converted from a checkbox; the Creator does not offer it on tag box choices) now follows `storeOthersAsComment`, so with it `false` its typed text is exported too. Other tag boxes are unchanged.

**What to do:** compile in merge mode, then backfill; see [Refresh stored rows](#refresh-stored-rows).

## Checkboxes from other form versions export empty cells {/* #checkboxes-from-other-form-versions */}

**What changed:** a checkbox or tag box with its own choices that a submission's form version did not have, because it was added in a later version or removed in an earlier one, now exports empty cells for that submission, Other and None included. In 0.9.2 a completed submission wrote `0` in every one of its columns, as if the respondent had seen it and left it. Submissions saved on a version that has the question are unchanged. See [Empty Cells](/docs/end-users/submissions/exporting-submissions#empty-cells).

**What to do:** no compile, only a backfill; see [Refresh stored rows](#refresh-stored-rows).

## Copies of selected choices export the source's Other {/* #copies-export-the-sources-other */}

**What changed:** a question that copies the choices a respondent picked (SurveyJS **Choices from question** with the selected mode) and has no **Other** of its own now exports its source question's **Other**. SurveyJS adds that **Other** to the copy once the respondent picked it on the source and typed a text, labelled with the typed text. In 0.9.2 the export had no category for it, so a radio button group or dropdown copy that picked it was empty, and a checkbox or tag box copy had no **Other** column. Now the copy's choices end with an **Other** labelled as on the source question, after the choices it already had. A merge compile preserves existing category IDs. A replace compile assigns IDs in current choice order, so reordering choices can change their IDs. A radio button group or dropdown copy gains an Other text column (`<question>__other_text`, `<question>--other_text` in csv-shoji) right after its own column, so later columns move one place to the right. When the copy picked **Other**, its own text takes precedence over the text from the source on the submission's form version. An answered checkbox or tag box copy writes `0` for an unpicked **Other** only if the visibility rule holds and either that source picked **Other** with text or that form version showed the copy's own **Other**. Otherwise the cell is empty. Carry Forward copies are unchanged: the Hub never adds the source's **Other**. See [Empty Cells](/docs/end-users/submissions/exporting-submissions#empty-cells).

**What to do:** compile with `replace=true`, then backfill; see [Refresh stored rows](#refresh-stored-rows).

## Refresh stored rows {/* #refresh-stored-rows */}

Copies of copied choices, copies of a source's Other, and Other text need a compile, then a backfill: without the compile, new submissions keep the 0.9.2 output too. Checkboxes from other form versions need only the backfill. Pick the compile by what the form holds:

| The form has | Compile (`POST forms/{formId}/reporting/compile-schema`) | Why |
| --- | --- | --- |
| Checkboxes or tag boxes copying from a question that copies its own choices | `replace=true` | A merge compile keeps a copy's rule only when the stored schema already had the same one. A schema compiled by 0.9.2 has none for these copies, so their cells stay empty. A `replace=true` compile also drops the columns of any checkbox or tag box the current form no longer has. |
| Questions copying the selected choices of a question with Other (**Choices from question**) | `replace=true` | A merge compile adds the **Other** category, but it drops the rule of a checkbox or tag box copy, whose choices changed, so its unpicked cells stay empty. A radio button group or dropdown copy needs only the merge, and `replace=true` is the one compile that fixes both. |
| Checkboxes with Other and a choice comment box, or tag boxes with Other, a choice comment box and `storeOthersAsComment: false` | Merge mode (no `replace`) | A merge compile records that the Other text is in the value and keeps every choice the stored schema knows. A replace compile drops a choice removed from the form, and a stored answer with that choice then exports as typed Other text. |
| Checkboxes or tag boxes added or removed after the form collected submissions | None (or the one the rows above call for) | Each submission is checked against the form version it was saved on when its row is written, so a schema compiled by 0.9.2 works as it is. A compile with `replace=true` drops the columns of a checkbox the current form no longer has. |
| Copies, and checkboxes or tag boxes with Other and a choice comment box | Your call | `replace=true` fixes the copies, at the cost above for any of those checkboxes or tag boxes that lost a choice; merge mode keeps those answers, and checkbox and tag box copies stay empty. |

Then backfill with `force=true` (`POST forms/{formId}/submissions/backfill`), once with `completionScope=completed` (the default) and once with `completionScope=incomplete`, repeating each and passing the response's `nextAfterSubmissionId` as `afterSubmissionId` until `hasMore` is false. `hasMore: false` does not mean every row was rewritten: check each response's `failedSubmissionIds`, and when any are listed, fix their cause and rerun that scope from the start with `force=true`. Checkboxes from other form versions change only completed submissions, so for them alone `completionScope=completed` is enough.

In the Hub, **Rebuild reporting data…** with **Full recompile** compiles with `replace=true` and backfills with `force=true`. Use it for copies, for checkboxes with Other only when no choice was removed from them, and for checkboxes from other form versions only when no checkbox was removed; otherwise call the endpoints. A rebuild without **Full recompile** compiles in merge mode but skips rows that have not changed.

A form whose copied questions changed their mode, their source questions' choices, or whether they copy at all across form versions: a compile with `replace=true` uses the current visibility rule for old submissions. A compile without `replace` drops the rule of a copy whose rule differs between the compiled schema and the current form, which leaves its cells empty; follow it with a backfill with `force=true`. Neither compile restores a visibility rule from a version that was never compiled. For a copy's **Other**, the export also checks which question supplied it on the submission's own form version.
