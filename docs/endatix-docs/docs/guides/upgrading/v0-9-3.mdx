# Upgrade to Endatix 0.9.3

Release notes: [Endatix API v0.9.3](https://github.com/endatix/endatix/releases/tag/v0.9.3) and [Endatix Hub v0.9.3](https://github.com/endatix/endatix-hub/releases/tag/v0.9.3).

Most hosts upgrade with no steps. Act only if you send email through SendGrid or Mailgun, replace the SMTP transport in code, or run the Reporting preview (`ReportingModule` flag) and export the questions listed below. An upgrade that skips 0.9.2 also needs the [0.9.2 guide](/docs/guides/upgrading/v0-9-2).

## At a glance

| Change | Affects | Action |
| --- | --- | --- |
| [MailKit 5](#custom-smtp-transports-need-mailkit-5) | Code that implements `IMailTransport` or overrides `CreateTransport()` | Migrate and rebuild |
| [Sender display name](#emails-show-a-sender-name) | SendGrid and Mailgun hosts | Set `Sender:Name` |
| [Unanswered checkboxes](#unanswered-checkboxes-export-empty-cells) | Checkboxes and tag boxes that can be hidden or left unanswered | Merge, then backfill |
| [Conditional choices](#conditional-choices-export-empty-when-unpicked) | Choices with `choicesVisibleIf` or `visibleIf` | Backfill |
| [Questions missing from a version](#checkboxes-from-other-form-versions) | Checkboxes added or removed between form versions | Backfill (completed) |
| [Copies of copied choices](#copies-of-copied-choices) | A copy whose source copies too | Replace or merge, then backfill |
| [The source's Other in a copy](#copies-export-the-sources-other) | Selected-mode copies with no Other of their own | Merge, then backfill |
| [Other text with a comment box](#other-text-with-a-choice-comment-box) | Checkboxes with Other and a choice comment box | Merge, then backfill |
| [Choice comment columns](#choice-comments-export-as-text-columns) | Choices with `showCommentArea: true` | Allow new headers; merge, then backfill |
| [Numeric matrix codes](#numeric-matrix-columns-keep-their-codes) | Radio matrices with numeric column values | Merge; handle a `409` |
| [Crunch rankings and dates](#crunch-rankings-and-dates) | Shoji codebooks imported into Crunch | Check existing datasets |

Every Reporting action uses one procedure, [Refresh stored rows](#refresh-stored-rows). Until you run it, exports keep the values stored when each submission was saved.

## Custom SMTP transports need MailKit 5

The SMTP sender runs on MailKit 5 and MimeKit.Core 5. The built-in sender needs no change. Code that implements `IMailTransport` or overrides `SmtpEmailSender.CreateTransport()` must move to the MailKit 5 request API and rebuild. A leftover `MimeKit` 4 reference fails the build with `CS0433`. See [Upgrade a custom SMTP transport to MailKit 5](/docs/developers/api/email-providers#upgrade-a-custom-smtp-transport-to-mailkit-5).

## Emails show a sender name

Stored-template emails now send with a display name, and on SendGrid and Mailgun that is new: recipients see `Endatix <your address>` unless you set `Endatix:Integrations:Email:Sender:Name`, or turn on a brand pack. The address is unchanged. See [Deployment sender](/docs/configuration/settings/email-settings#deployment-sender).

## Reporting export changes

Full rules: [Special answers in exports](/docs/developers/api/special-answers-in-exports). Crunch imports an empty cell as No Data.

### Unanswered checkboxes export empty cells

An unanswered checkbox or tag box with its own choices writes empty cells, not `0`, in every column when the respondent may not have seen it: in an incomplete submission, or when a `visibleIf` or `visible: false` on the question or anything holding it could hide it. A question nothing could hide, skipped in a completed submission, still writes `0`. Merge first so the schema records which questions can be hidden; a backfill alone only empties incomplete submissions.

### Conditional choices export empty when unpicked

An unpicked choice under `choicesVisibleIf` or its own `visibleIf` exports empty, even on an answered question. The export reads the condition from the submitted form version, so a backfill is enough.

### Checkboxes from other form versions

A checkbox or tag box that the submission's form version did not have exports empty cells for that submission, instead of `0`. Only completed rows change.

### Copies of copied choices

A copy whose source copies its own choices (`pick` copies `aware`, which copies `brands`) writes `0` for a choice the respondent was shown and did not pick. Merge leaves those cells empty when it cannot prove the choice was shown; replace gives exact `0`s. Choose with the [mixed-history rule](#refresh-stored-rows).

### Copies export the source's Other

A **Choices from question** copy in selected mode with no Other of its own exports the source's Other as an extra category. A radio button group or dropdown copy also gains `<question>__other_text` after its answer column.

### Other text with a choice comment box

A checkbox with Other whose choice has **Add a comment box** exports its Other as `1` with the typed text, instead of `0` and an empty text. Radio button groups and dropdowns are unchanged.

### Choice comments export as text columns

Each choice with `showCommentArea: true` gets a text column, for example `brands__item2__comment` (`brands--item2--comment` in csv-shoji). Imports that expect a fixed set of headers must allow them. Backfill recovers only comments the answers stored.

A compile that would give a published header a second meaning returns `409` and keeps the previous schema: rename the question or choice that `detail` names, then compile again.

### Numeric matrix columns keep their codes

A radio matrix with numeric column values keeps the source code in the native codebook (`"20"`, labeled Low) and writes the category ID in Shoji CSV. Saved codebooks are not rewritten. A merge that cannot match a legacy codebook to a historical definition returns `409` with `The stored category identities of matrix '<question>' need a matching historical definition.` and saves nothing. Renaming does not help: the form keeps exporting as before, and replace is the only way forward, after the [comparison below](#refresh-stored-rows).

### Crunch rankings and dates

The Shoji codebook declares a ranking as one numeric array, not one numeric variable per choice, and gives dates and timestamps a display format. CSV columns are unchanged. A Crunch dataset created from an earlier codebook still has the old ranking variables: test an append on a copy, or import into a new dataset.

## Refresh stored rows

Choose a compile mode for the form, then backfill. A compile changes the schema, not stored rows.

| The form needs | Mode | Effect |
| --- | --- | --- |
| New columns, hide rules, Other text | Merge | Keeps category IDs and removed choices |
| Exact `0`s for copies of copies | Replace | Rebuilds from the current form |
| Only backfill fixes (conditions, versions) | None | Backfill reads the submitted version |

**Default to merge on a form with history.** Replace can drop columns, renumber category IDs, and reclassify a removed choice as Other text. Use it only after you compare before-and-after exports of the same submissions and accept the differences.

1. Compile, if needed: `POST forms/{formId}/reporting/compile-schema`, with `replace=true` for replace.
2. Backfill with `force=true` (`POST forms/{formId}/submissions/backfill`), once with `completionScope=completed` and once with `completionScope=incomplete`. Pass each `nextAfterSubmissionId` as `afterSubmissionId` until `hasMore` is `false`.
3. Check `failedSubmissionIds` on every page. If any are listed, fix the cause and rerun that scope from the start.

A rejected compile returns `409` with `errorCode: "ReportingSchemaAliasConflict"` for both a [comment header clash](#choice-comments-export-as-text-columns) and a [matrix codebook](#numeric-matrix-columns-keep-their-codes); `detail` says which. Do not backfill after it.

In the Hub, **Rebuild reporting data…** with **Full recompile** is replace plus a forced backfill. Without it, the Hub merges but skips unchanged submissions, so use the API for merge plus a forced backfill.
