# API Configuration

This guide covers how to configure the API layer of your Endatix application, including endpoints, routing, versioning, and other API behaviors.

## API Endpoints Configuration

Endatix provides a simplified way to configure API endpoints using the builder pattern.

### Basic API Configuration

Configure the API with sensible defaults:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseEndpoints();
});
```

This registers all Endatix API endpoints with default configurations.

### Custom API Configuration

For more control over API endpoints:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseEndpoints(endpoints => {
        endpoints.UsePrefix("/api/v{version:apiVersion}");
        endpoints.EnableVersioning();
        endpoints.ScanAssembly(typeof(Program).Assembly); // Scan for endpoints in your assembly
    });
});
```

## API Versioning

Endatix supports API versioning to maintain backward compatibility as your API evolves.

### Basic API Versioning

Enable API versioning with default settings:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseVersioning();
});
```

### Custom API Versioning

Configure API versioning with custom options:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseVersioning(options => {
        options.DefaultApiVersion = new ApiVersion(1, 0);
        options.AssumeDefaultVersionWhenUnspecified = true;
        options.ReportApiVersions = true;
        options.ApiVersionReader = ApiVersionReader.Combine(
            new UrlSegmentApiVersionReader(),
            new HeaderApiVersionReader("X-Api-Version")
        );
    });
});
```

### API Versioning in appsettings.json

Configure API versioning in your `appsettings.json`:

```json
{
  "Endatix": {
    "Api": {
      "Versioning": {
        "Enabled": true,
        "DefaultVersion": "1.0",
        "AssumeDefaultVersionWhenUnspecified": true,
        "ReportApiVersions": true,
        "Readers": {
          "UrlSegment": true,
          "Header": "X-Api-Version",
          "QueryString": "api-version"
        }
      }
    }
  }
}
```

## API docs

The API serves its OpenAPI document, an interactive reference built with [Scalar](https://scalar.com), and Swagger UI:

| What | Path |
| --- | --- |
| API docs page (Scalar) | `/api-docs` |
| Swagger UI | `/swagger` |
| OpenAPI document | `/swagger/alpha-version/swagger.json` |

Scalar reads the document, lists every endpoint, and sends requests from the page. To call an endpoint that needs a
signed-in user, open **Authentication**, choose `JWTBearerAuth`, and paste an access token. The page never fills in a
token for you.

Configure the docs in `appsettings.json`:

```json
{
  "Endatix": {
    "Api": {
      "Docs": {
        "Enabled": true,
        "Path": "/api-docs",
        "SwaggerUi": {
          "Enabled": true,
          "Path": "/swagger"
        }
      }
    }
  }
}
```

<Settings>
<Setting name="Endatix:Api:Docs:Enabled" default="true">
Serves the OpenAPI document, the API docs page, and Swagger UI. `false` turns all of them off.
</Setting>
<Setting name="Endatix:Api:Docs:Path" default="/api-docs">
The path of the API docs page. It must start with `/`. An empty value or `/` serves the page at `/api-docs` and logs a
warning at startup. The root `/` then redirects to the page, unless your app maps its own `GET /`, which always wins.
</Setting>
<Setting name="Endatix:Api:Docs:SwaggerUi:Enabled" default="true">
Serves Swagger UI. It is on by default in this release and turns off by default in the next one. While it is not set,
the API logs one line at startup about the change. Set it to `true` to keep Swagger UI, or to `false` to turn it off
now.
</Setting>
<Setting name="Endatix:Api:Docs:SwaggerUi:Path" default="/swagger">
The path of Swagger UI. It must start with `/`.
</Setting>
<Setting name="Endatix:Api:UseSwagger" status="deprecated" replacedBy="Endatix:Api:Docs:Enabled">
The old name of `Docs:Enabled`. It still works when `Docs:Enabled` is not set. When both are set to different values,
`Docs:Enabled` wins and the API logs a warning at startup.
</Setting>
<Setting name="Endatix:Api:SwaggerPath" status="deprecated" replacedBy="Endatix:Api:Docs:Path">
The old name of `Docs:Path`. It still works when `Docs:Path` is not set. When both are set to different paths,
`Docs:Path` wins and the API logs a warning at startup.
</Setting>
</Settings>

### Swagger UI during the move to Scalar

Earlier releases showed Swagger UI at `/api-docs`. This release shows Scalar there and keeps Swagger UI at `/swagger`.
An old bookmark to `/api-docs/index.html` opens Swagger UI while it is on, and the API docs page once it is off.

From the next release, Swagger UI is off unless you turn it on. To keep it, set the setting now:

```json
{
  "Endatix": {
    "Api": {
      "Docs": {
        "SwaggerUi": { "Enabled": true }
      }
    }
  }
}
```

### When both pages ask for one path

If Swagger UI and the API docs page ask for the same path, the API still starts. Swagger UI keeps the path, since that
address showed Swagger UI before. The API docs page moves to `/api-docs`, or to `/scalar` when the shared path is
`/api-docs`. A warning at startup names both paths. For example, `"SwaggerPath": "/swagger"` serves Swagger UI at
`/swagger` and Scalar at `/api-docs`.

To choose the paths yourself, set `Docs:Path` or `Docs:SwaggerUi:Path`.

## Rate Limiting

Endatix provides support for API rate limiting to protect your API from abuse.

### Basic Rate Limiting

Enable rate limiting with default settings:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseRateLimiting();
});
```

### Custom Rate Limiting

Configure rate limiting with custom options:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.UseRateLimiting(options => {
        options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(context =>
        {
            return RateLimitPartition.GetFixedWindowLimiter(
                partitionKey: context.User.Identity?.Name ?? context.Request.Headers.Host.ToString(),
                factory: partition => new FixedWindowRateLimiterOptions
                {
                    AutoReplenishment = true,
                    PermitLimit = 100,
                    Window = TimeSpan.FromMinutes(1)
                });
        });
    });
});
```

### Rate Limiting Settings in appsettings.json

Configure rate limiting in your `appsettings.json`:

```json
{
  "Endatix": {
    "Api": {
      "RateLimiting": {
        "Enabled": true,
        "PermitLimit": 100,
        "WindowInMinutes": 1,
        "QueueLimit": 0,
        "ReplenishmentPeriodInSeconds": 1,
        "TokensPerPeriod": 1,
        "AutoReplenishment": true
      }
    }
  }
}
```

## Response Formatting

Configure how API responses are formatted:

```csharp
builder.Host.ConfigureEndatix(endatix => {
    endatix.Api.ConfigureResponses(options => {
        options.UseEnvelopePattern = true;
        options.IncludeExceptionDetails = builder.Environment.IsDevelopment();
        options.UseHyphenCasePropertyNames = true;
    });
});
```

### Response Formatting Settings in appsettings.json

Configure response formatting in your `appsettings.json`:

```json
{
  "Endatix": {
    "Api": {
      "Responses": {
        "UseEnvelopePattern": true,
        "IncludeExceptionDetails": false,
        "UseHyphenCasePropertyNames": true,
        "DefaultPageSize": 25,
        "MaxPageSize": 100
      }
    }
  }
}
```

## Custom Endpoint Configuration

Endatix uses a modern, FastEndpoints-based approach for defining API endpoints. Here's how to create a custom endpoint:

```csharp
public class GetCustomerRequest
{
    public int Id { get; set; }
}

public class GetCustomerResponse
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
}

public class GetCustomerEndpoint : Endpoint<GetCustomerRequest, GetCustomerResponse>
{
    private readonly ICustomerService _customerService;

    public GetCustomerEndpoint(ICustomerService customerService)
    {
        _customerService = customerService;
    }

    public override void Configure()
    {
        Get("/customers/{Id}");
        Version(1);
        Summary(s =>
        {
            s.Summary = "Get a customer by ID";
            s.Description = "Retrieves a customer by their unique identifier";
            s.ExampleRequest = new GetCustomerRequest { Id = 1 };
        });
    }

    public override async Task HandleAsync(GetCustomerRequest req, CancellationToken ct)
    {
        var customer = await _customerService.GetCustomerByIdAsync(req.Id, ct);
        
        if (customer == null)
        {
            await SendNotFoundAsync(ct);
            return;
        }
        
        var response = new GetCustomerResponse
        {
            Id = customer.Id,
            Name = customer.Name,
            Email = customer.Email
        };
        
        await SendOkAsync(response, ct);
    }
}
```

## Best Practices

1. **API Versioning:** Always version your API to maintain backward compatibility
2. **Rate Limiting:** Apply rate limiting to protect your API from abuse
3. **Response Formatting:** Use consistent response formats across all endpoints
4. **Documentation:** Keep your endpoint summaries and descriptions accurate, since the API docs page shows them
5. **Security:** Ensure all sensitive API endpoints are properly secured with authentication and authorization
