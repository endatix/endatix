# Reverse Proxy Deployment

When you finish, redirects and cookies use the public https host, and anonymous rate limits use one visitor address. Leaving the allowlists empty does not turn the visitor address on. `Endatix:Hub:HubBaseUrl` is the public Hub origin used in links. It is not a proxy address.

If Hub or the API is served under a path prefix such as `/app` or `/api`, start with [Subfolder Deployment](/docs/building-your-solution/deployment/subfolder-deployment), then apply the settings below.

## What you can rely on

Two jobs stay separate. Host headers are not the client IP.

- **Public URL.** `Host`, `X-Forwarded-Host`, and `X-Forwarded-Proto` tell the API the public host and scheme. The API applies them only when `Endatix:Hosting:ReverseProxy:Enabled` is true and the TCP peer is a known proxy (or Development trust-all is on). Azure Front Door overwrites host and proto. Without them the API sees the internal URL, share links break, and browsers drop secure cookies after a scheme change.
- **Visitor address.** `X-Forwarded-For` is the only header used for the client IP. The proxy appends the peer it saw. The API reads from the right, skips proxies you listed, and keeps the first other address. It then replaces the header with that one address, so a caller cannot rotate the rate-limit bucket by prepending a fake hop.

## What this setup does not do

- `0.0.0.0/0` and `::/0` are rejected in both allowlists.
- `X-Azure-ClientIP`, `CF-Connecting-IP`, `True-Client-IP`, and `X-Real-IP` do not win. The API removes them. `X-Azure-SocketIP` is not read. The appended `X-Forwarded-For` hop is the same fact.
- Azure Static Web Apps `globalHeaders` do not pass a client IP. Those entries are response headers (cache, CORS) and they do not apply to API responses.
- An empty `ENDATIX_TRUSTED_PROXIES` sends no visitor address. Hub cannot see the socket once the browser already sent `X-Forwarded-For`. A filled list is safe only when clients cannot reach Hub except through those proxies.
- `TrustAllProxiesInDevelopment` trusts every peer, and only when the API environment is Development.

## No proxy in front

Leave `Endatix:Hosting:ReverseProxy:Enabled` false and `ENDATIX_TRUSTED_PROXIES` empty. Rate limits use the connection IP. A caller-supplied `X-Forwarded-For` does not change the bucket. Stop here.

## API behind a proxy

1. Set `Endatix:Hosting:ReverseProxy:Enabled` to `true`.
2. Set `KnownProxies` or `KnownNetworks` to the proxy that opens the connection to the API, not to the visitor. An empty list keeps loopback only, so a cloud load balancer is an untrusted peer and the visitor address is dropped.
   When Hub calls the API from its server, Hub opens that connection. Add Hub's outbound address too, or every visitor who goes through Hub shares Hub's rate-limit bucket.
3. Leave `TrustAllProxiesInDevelopment` true for local Development only.
4. Confirm the proxy appends the peer it saw onto `X-Forwarded-For` and sets `X-Forwarded-Proto` to the public scheme. Use the recipe for your proxy below.

```json
{
  "Endatix": {
    "Hosting": {
      "ReverseProxy": {
        "Enabled": true,
        "TrustAllProxiesInDevelopment": true,
        "KnownProxies": [],
        "KnownNetworks": ["10.0.0.0/8"]
      }
    }
  }
}
```

HSTS and HTTPS redirection are off when the proxy is enabled, because TLS ends at the edge. To keep those policies on the API, set `Endatix:Hosting:UseHsts` and `Endatix:Hosting:UseHttpsRedirection` to `true`.

`Program.cs` stays:

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Host.ConfigureEndatix();

var app = builder.Build();
app.UseEndatix();

app.Run();
```

<Settings>
<Setting name="Endatix:Hosting:ReverseProxy:KnownProxies" default="[]">
IP addresses of proxies allowed to supply `X-Forwarded-For`. Used only when `Enabled` is true and Development trust-all is not in effect.
</Setting>
<Setting name="Endatix:Hosting:ReverseProxy:KnownNetworks" default="[]">
CIDRs of those proxies, such as a load balancer or ingress subnet. Do not use `0.0.0.0/0` or `::/0`.
</Setting>
<Setting name="ENDATIX_TRUSTED_PROXIES" default="empty">
Comma-separated IPs and CIDRs in front of Hub. Hub forwards one visitor address only when this is set. See [Hub environment variables](/docs/developers/hub/environment).
</Setting>
</Settings>

## Hub behind a proxy

1. Set `AUTH_URL` to the public origin and `AUTH_TRUST_HOST=true` so sign-in uses the public host. For a single-domain `/app` setup:

```env
NEXT_PUBLIC_BASE_PATH=/app
ENDATIX_BASE_URL=https://yourdomain.com
ENDATIX_API_PREFIX=/api
AUTH_URL=https://yourdomain.com/app/api/auth
AUTH_TRUST_HOST=true
ENDATIX_TRUSTED_PROXIES=10.0.0.0/8
```

2. Set `ENDATIX_TRUSTED_PROXIES` to the proxies in front of Hub. Comma-separated IPs or CIDRs. `0.0.0.0/0` and `::/0` are rejected. The API allowlist is separate.
3. Lock Hub so clients cannot skip that proxy. If they can, they can write `X-Forwarded-For` themselves and Hub will forward it. Hub does not check the socket.

`AUTH_TRUST_HOST=true` is required for Auth.js behind a proxy. See [Endatix JWT authentication](/docs/building-your-solution/authentication/endatix-jwt).

## Nginx

Nginx's default proxy config sets `Host` to the internal upstream and does not send `X-Forwarded-For`. `X-Real-IP` is ignored.

1. Append the peer Nginx saw, and keep the public host and port.
2. On a non-standard port such as `localhost:8080`, use `$http_host`. `$host` strips the port and redirects land on port 80.
3. Turn off absolute redirects so a trailing-slash redirect from `/app` to `/app/` keeps the port.

```nginx
proxy_set_header Host $http_host;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Host public.example.com;
proxy_set_header X-Forwarded-Proto $scheme;
absolute_redirect off;
```

Replace `public.example.com` with the approved public host. Do not forward a caller-supplied `X-Forwarded-Host`; the API trusts that header from a known proxy and uses it for `Request.Host` and generated links.

## Azure Front Door

Front Door appends the socket IP onto `X-Forwarded-For` and overwrites `X-Forwarded-Host` and `X-Forwarded-Proto`. It also sets `X-Azure-ClientIP`, which can differ from that socket. The API ignores `X-Azure-ClientIP`.

1. Put Front Door's backend ranges in `KnownNetworks` on the API, and the same ranges in `ENDATIX_TRUSTED_PROXIES` when Hub sits behind Front Door. In Azure the service tag is `AzureFrontDoor.Backend`. Use the current ranges from that tag, not `0.0.0.0/0`.
2. If the origin is also reachable without Front Door, require header `X-Azure-FDID` with your Front Door resource id so only that instance can call the origin. On Static Web Apps that is `forwardingGateway.requiredHeaders`, in the recipe below.

## Cloudflare

Cloudflare appends the previous hop onto `X-Forwarded-For`. It also sets `CF-Connecting-IP`. The API ignores that header. A Worker can change `x-real-ip`, so do not switch the app to `CF-Connecting-IP` or Enterprise `True-Client-IP`.

1. Put [Cloudflare's published IP ranges](https://www.cloudflare.com/ips/) in `KnownNetworks` and in `ENDATIX_TRUSTED_PROXIES`. Refresh the list when Cloudflare publishes new ranges.
2. Leave Pseudo IPv4 off. The Overwrite Headers mode replaces `X-Forwarded-For` with a fake IPv4.

## Azure Static Web Apps

`globalHeaders` in `staticwebapp.config.json` does not set the visitor IP. Do not add `X-Forwarded-For` there.

When Hub on Static Web Apps is reached through Azure Front Door, `forwardingGateway` and its `requiredHeaders` restriction need the Static Web Apps Standard plan. Free-plan deployments cannot use that restriction.

1. List the public host so redirects keep it.
2. Require your Front Door id on every request.
3. Set `ENDATIX_TRUSTED_PROXIES` to the proxies that appended the hop, as in the Front Door recipe.

```json
{
  "forwardingGateway": {
    "allowedForwardedHosts": ["yourdomain.com"],
    "requiredHeaders": {
      "X-Azure-FDID": "692a448c-2b5d-4e4d-9fcc-2bc4a6e2335f"
    }
  }
}
```

Replace the id with the Front Door resource id from the Azure portal. Requests without that header are rejected by Static Web Apps.

## Check the visitor address

- Call the API directly and change `X-Forwarded-For` between attempts. The rate-limit bucket stays the connection IP.
- Call through the proxy as two visitors. You get two buckets.
- Prepend a fake address. The bucket stays the address the proxy appended.
